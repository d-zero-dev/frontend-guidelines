# CSS コーディング規約

> 実装レイヤー選定（`dzero-tech-selection`）を経ていない場合は先にそちらを読むこと。詳細は [CSS ガイドライン](https://guidelines.d-zero.co.jp/css/) を参照。

## 実装規範

### 姿勢

- 「何故か解らないけど出来た」を許さない。プロパティ・セレクタひとつひとつの作用を理解して書く
- 常に別解（メンテナンス性優先・パフォーマンス優先など）を考えながら最適な方法を選ぶ
- リントエラー（Stylelint / Prettier）は例外なく必ず修正する。`stylelint-disable` コメントは原則使わず、ルールが現状にそぐわない場合は Config ファイル（`.stylelintrc` の `selector-class-pattern` 等）の変更を提案する

### ファイル構成

- 1 ファイル 1 コンポーネント。ファイル名はコンポーネント名と一致させる（`c-header` → `__assets/_libs/component/c-header.css`）
- `__assets/htdocs/css/style.css` は `@import` のみでスタイルを定義しない。インポートは CSS レイヤー（`reset` / `base` / `general` / `components` / `main`）で分類する
- `base/root.css` のセレクタは `:root` のみ。グローバルなカスタムプロパティ（Figma のバリアブル由来を含む）はここに定義する
- `general/` は素の要素へのスタイル（ファイル名はタグ名、セレクタはタイプセレクタのみ）。ページ全体に影響するため**必要最小限**にし、コンポーネントで定義できるものはコンポーネント内で定義する。「サイト全体で共通」という判断はほとんどの場合失敗するので推奨しない

### セレクタ

- 1 階層目のセレクタはコンポーネントの定義であり、CSS ファイル内に一度だけ登場させる
- エレメント・状態変化は BEM 記法に従った**フラットなセレクタ**で定義し、コンポーネント内のすべてのスタイルを明示的に記述する（ネストで書かない。フルのクラス名が検索にヒットすることを優先）
- ID セレクタでスタイルを定義しない
- タイプセレクタは利用可能だが、コンポーネントはコンポーネントを内包できるため注意する。エレメントにクラスを付けて対象を限定するか、`>` 結合子で影響範囲を限定する

### 記述順

ルール内は次の順で記述する: 1. 変数定義 → 2. コンポーネント自体のスタイル → 3. 擬似要素 → 4. 状態変化（メディアクエリ → 擬似クラス → 属性 → 状態クラス）→ 5. エレメント以外の子孫要素 → 6. 結合子セレクタ → 7. 子孫要素に影響のある状態変化（エレメントを巻き込む状態変化は後ろに書く）

### 値

- `font-size` は相対値で、意図を計算式で明示する（`font-size: calc(14 / 16 * 1em)`。`1.2em` のような根拠の見えない値は不可）。コンポーネントのルートは `rem`、エレメントは `em` を推奨
- `%` / `vw` / `vh` は何を基準にしているか `calc()` で明示する（`calc(100% / 3)` は可、`33.3%` は不可）。`100%` / `100vw` / `100vh` 以外の基準は避ける
- 原則、論理プロパティを使う（`padding-top` → `padding-block-start`）。論理プロパティとして機能しないショートハンドは避け、`transform` は関数でなく `translate` / `rotate` / `scale` プロパティを使う
- プロジェクトのカスタムプロパティ（デザイントークン）に対応する値を直接書かない。`var()` で参照する
  <!-- 暫定ルール: stylelint（declaration-strict-value 系）によるトークン強制を linters に提案中。導入されたらこの項目は削除する -->
- `line-height` は絶対値（px）で書かず、`font-size` との比率で書く
  <!-- 暫定ルール: stylelint（declaration-property-unit-disallowed-list）による line-height の px 禁止を linters に提案中。導入されたらこの項目は削除する -->

### カスタムプロパティ・関数

- カスタムプロパティは積極的に採用する
- レスポンシブのブレークポイントは規定のカスタムクエリー（`--xs` 〜 `--xl`、`--*-lte` / `--*-gt`、`--hr`）を利用する
- 関数の定義は原則禁止（CSS 標準の関数と PostCSS の `resolve` のみ使用可）

### 命名

クラス名・識別子の命名は `dzero-html` の「命名」に従う。

## レビュー観点

- `general/` に安易な追加がないか（コンポーネントで定義できるものが混ざっていないか）
- セレクタがネストで書かれていないか。1 ファイルに複数コンポーネントが定義されていないか
- タイプセレクタが内包コンポーネントに影響しうる書き方になっていないか
- 根拠の見えない値（基準不明の `%`、計算式のない `em`、マジックナンバー）がないか
- カスタムプロパティで置き換えられる直書きの値がないか
- `stylelint-disable` コメントが安易に挿入されていないか
