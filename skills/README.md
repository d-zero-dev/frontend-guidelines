# Agent Skills

案件プロジェクトに配布する、AI コーディングエージェント（Claude Code / Cursor 等）向けのスキル群。

## 配布の仕組み

- 案件側は [vercel-labs/skills](https://github.com/vercel-labs/skills) CLI で取り込む。`package.json` の `skills:sync` スクリプト（バージョン固定の `npx skills add <このリポジトリの skills/ の tree URL>#main --copy -y`）を実行すると `.claude/skills/` に実体がコピーされる
- **`main` ブランチが配布チャネル**。`dev` へのマージでは配布されず、`main` へマージした時点で全案件から取得可能になる
- 案件側ではコピーされたファイルを git にコミットし、更新差分は PR でレビューする

## 執筆規約

### 命名

- スキル名（ディレクトリ名・frontmatter の `name`）は `dzero-` プレフィックスを付ける（案件側 `.claude/skills/` での他スキルとの衝突回避）

### frontmatter

Cursor との互換性のため、次のフィールドのみ使用する:

```yaml
---
name: dzero-xxx
description: <このスキルが何をするか + どんな場面で使うか（起動トリガーとなる語彙を含める）>
paths: ['**/*.css'] # 特定のファイルタイプに紐づくスキルのみ設定する
license: CC-BY-NC-SA-4.0
---
```

- `paths` は Cursor・Claude Code の両方でサポートされる（Cursor では[スキルを特定ファイルにスコープするフィールド](https://cursor.com/en-US/docs/skills#scoping-a-skill-to-specific-files)として使用可）。技術軸スキル（css / js / html / a11y）のように対象ファイルタイプが明確な場合に設定する。判断・レビュー系などファイルタイプに紐づかないスキルでは省略する
- `context` / `hooks` 等その他の Claude Code 拡張フィールドは**使わない**（Cursor では機能しないため）
- `description` はエージェントの自動起動判定に使われる。「CSS を書く・編集するとき」のように具体的な使用場面と語彙を明記する

### 構成

- 技術軸スキル（css / js / a11y / html）は「実装規範」のみで構成する。レビュー観点は別セクションとして書かない（規範の言い換えの二重管理になるため）。レビューは `dzero-review` が各規範に照らして行う
- 技術軸スキルの冒頭には、実装レイヤー選定（`dzero-tech-selection`）を経たかを確認するガード文を置く
- 参照ファイルが必要な場合は**スキルフォルダ内**の `references/` に置く。スキルはフォルダ単位で配布されるため、フォルダ外（`../../src/` 等）への参照は案件側に届かない

### 内容ポリシー

- 書いてよいのは**根拠のある内容のみ**:
  1. `src/`（ガイドライン本文）に実在する規範の蒸留
  2. トリアージを経て合意された項目
- ソースにない「それっぽい一般論」で埋めることを**禁止**。根拠が足りないセクションは見出しと TODO コメントだけの空のまま残す
- **精神論・心構えは書かない**（「理解して書く」「品質を意識する」等）。エージェントの行動を変えない宣言はトークンの無駄。「X の場合は Y する」という実行・検証可能な形に変換できる場合のみ、その形で書く（人間向けの `src/` に残すのは問題ない）
- **[linters](https://github.com/d-zero-dev/linters) の共通設定で既に強制されているルールはスキルに書かない**。強制ハーネス（lint）側が担保するため、原則として重複させる必要がない（ガイドライン本文に「Stylelint / Markuplint によって警告されます」とあるルールが該当）
- lint で機械的に担保**できるがまだ未導入**のルールは、スキルに書かず linters への追加を提案する。lint 導入までの暫定として記載する場合は、解消条件と削除メモを必ず付ける
- ルールの内容がガイドライン本文（`src/`）に関わる場合は、**同じ PR で `src/` とスキルの両方を更新**して乖離を防ぐ

### ルールの追加

新しいルールの追加・分類には、このリポジトリの `.claude/skills/rule-authoring`（非配布・メンテナー用）を使うこと。ルール化の要否・抽象度・恒常性・宛先のトリアージを経てから執筆する。
